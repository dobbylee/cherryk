# 구현 리뷰

`AGENTS.md`와 메인 에이전트가 지정한 목적·변경 파일·관련 결정·검증 결과를 기준으로
리뷰한다. 제공되지 않은 관련 지침만 추가로 읽는다. 활성 작업 상세는 필요할 때만
읽으며 전체 계획 이력이나 전체 대화를 요구하지 않는다.

## 범위와 근거

- 지적 대상은 이번 변경으로 생기거나 악화된 문제이다. `git status`, staged/unstaged
  diff, 검토 대상 신규 파일의 전체 내용을 확인한다. 목록에서 빠진 변경은 메인
  에이전트에 알리고 리뷰 범위를 확인한다.
- 호출자·계약·설정·테스트·관련 결정은 변경되지 않았어도 근거 확인을 위해 읽을 수
  있다. 관련 없는 정리를 요청하거나 파일을 수정하지 않는다.
- 구체적인 버그, 회귀, 보안·개인정보·데이터 손실 위험, 계약·스키마 이탈, 누락된
  검증을 찾는다. 취향이나 추측만으로 지적하지 않는다.
- 검증 통과는 부모가 제공한 명령과 결과로 확인하며 필요한 좁은 읽기 검사를 한다.
  개발 서버를 조작하거나 전체 빌드·테스트를 중복 실행하지 않는다.

## 변경별 확인

- API·모듈: TypeScript 계약/fixture와 Spring DTO·컨트롤러 테스트의 호환성,
  호출 방향, 트랜잭션과 엔티티 직렬화 경계를 확인한다.
- 인증·데이터·AI: `decisions.md`의 해당 불변 조건과 거부 경로를 확인한다. 권한,
  CSRF, 로컬 인증 격리, 학습자 응답의 정답 노출, 원본·비밀·사용자 텍스트의 로그
  유출, 공급자 실패 시 사용량 예약 해제 중 변경과 관련된 항목을 추적한다.
- 테스트·운영: 환경 장애를 성공/skip/캐시로 숨기지 않는지, 테스트가 실제 공급자나
  Production 데이터에 의존하지 않는지, 정확한 SHA·최소 권한·롤백 경계를 보존하는지
  확인한다. 캐시나 실행 순서에 의존하는 테스트 변경도 검토한다.
- 하네스: `workflow.md`의 실패 근거와 범위가 좁은 검증을 확인한다. 규칙을 옮기거나
  줄인 경우 원문과 대조하여 안전장치가 새 위치에 남고 진입 문서에서 도달하는지
  확인한다. 모델 설정의 효력은 실제 세션과 공식 문서로 확인한다.

지적 사항을 심각도 순으로 나열한다. 각 항목에 파일 경로, 줄 번호, 재현 조건과
구체적인 영향, 최소 수정안을 포함한다. 지적 사항이 없다면 정확히 다음을 출력한다.
